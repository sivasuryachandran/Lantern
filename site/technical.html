Technical flow

Agents route. Code decides.

A deterministic record service sits between Mattermost and the chart. It uses no model. Everything it does is checked, logged and safe to replay.

Validation

What has to be true before anything changes.

A claim card is accepted only if

  • its quote is an exact substring of the original patient post;
  • it names an active order of that topic;
  • it cites the current chart version;
  • its status is possible_discrepancy, never confirmed.

A decision counts only if

  • the author is a user with the doctor role, matched by user_id;
  • it is posted in doctor-review as a reply in that case's thread, unedited;
  • it uses the DECIDE format and names the current chart version;
  • the case is already nurse-confirmed.

Everything a patient can ever read from the service is a fixed template or the doctor's own words. Side effects are keyed and idempotent, so a restart never creates a duplicate case, thread or patient message.

Evidence receipts

How a cited fact earns its check mark.

The lookup tool

A plain-code endpoint on the record service. Each call is stored with a lookup number, entry, chart version, label, value, time and the agent's name.

GET /chart/101/proc-1?agent=care-coordinator

→ citation: [proc-1 v3 · lookup #31 = Thu 9:00]

The check, in code

  • ✓ verified: the lookup exists and matches entry, version, agent, patient and value.
  • ⚠ unverified: no matching lookup, wrong value, entry, version, agent or patient.
  • ⚠ stale: the chart has moved past the version that was read.
  • Text without a citation is labelled unverified interpretation.

Limit: the agent name in a lookup request is self-declared unless a lookup key is set, so the log shows what was fetched on this machine, not who authenticated.

Built on Switch

Agents in the room, people in the room, Switch in between.

Lantern is a Switch room group in spirit: two AI agents, intake and care-coordinator, work in staff rooms next to nurses and a doctor. Switch decides who is in which room; a small service keeps the record exact.

Reproduce it

From a clean machine.

  1. Clone the repo, python3 -m venv .venv && .venv/bin/pip install pyyaml, run the tests.
  2. Start Switch and its Mattermost; create intake and care-coordinator in Switch Console with the instructions in docs/agents/.
  3. Run scripts/setup_mattermost.py to create the users and the nine rooms from config/roles.yaml.
  4. Start the service with scripts/start.sh; open http://127.0.0.1:8099/.
  5. Play the humans with scripts/demo_driver.py (add --real when the real agents are in the rooms).

Gotchas we hit

Things that cost us time.

Switch ids are not Mattermost ids

Switch's own message ids (they start with sw_) differ from Mattermost's, so intake looks up the real forwarded id through a small tool.

Progress posts look like claims

Switch's "Working…" posts had to be ignored by the receipt check.

Personal access tokens can be off

Our local Mattermost had them disabled, so record-bot logs in and uses a session token.

Agents answer where they are told

care-coordinator had to be told to reply inside the case thread, not the channel.

Features

Everything Lantern does.

One shared record for a ward, run in Switch rooms. All data is fictional.

The ward: nine private rooms

  • Four patient rooms (101 to 104). Only the patient and record-bot are in them; no agent ever is.
  • nurse-station and doctor-review for the care team and the agents.
  • Three feeds: orders (every chart change), medication (every dose, apart from orders), room-service (tray and turnover tasks).
  • Isolation is room membership: one patient cannot open another's room.

The case loop

  • A patient's passing remark is checked against their active orders; the quote stays exact.
  • A nurse confirms or rejects. Nothing reaches a doctor on an agent's word alone.
  • The care-coordinator cites chart facts from a logged lookup; the service marks each ✓ verified or ⚠ stale from its own log.
  • Only a verified doctor can decide. A nurse's DECIDE is refused and logged. The patient gets the doctor's exact words.
  • Handoff: the owner hands over open or resolved cases, the next nurse accepts, and ownership changes everywhere.

Commands

  • CONFIRM, REJECT, DECIDE + EXPLAIN, GIVEN, HANDOFF, ACCEPT, TIMELINE.
  • ADVICE: dictated doctor advice, logged as advice only, with a draft DECIDE the doctor sends herself.
  • REMIND: a follow-up by voice (in 20 min, 11:00, 9am), posted back when due, mirrored to Calendar.
  • NOTE: a dictated note for the record; it changes nothing.
  • DONE, DISCHARGE, READY for room service, turnover and room readiness.

Agents

  • intake and care-coordinator run as OpenCode agents in Switch Console, with instructions in the repo.
  • interpreter: translates patient to staff and doctor to patient, always beside the original, and reads aloud.
  • scribe: files dictated notes, drafts reminders for a person to send, keeps the shift record current.
  • Stand-in agents implemented in code (python -m lantern simagents) run the same behavior when the Switch agents are unreachable.
  • Internal code-only tools: chart lookup, receipt checker, room ledger, task tracker, scheduler, audit log.

Voice and language

  • Built and run by voice with Wispr Flow: hold Fn and speak commands, prompts and notes.
  • Snippets turn a phrase into the exact command prefix; the dictionary turns "at intake" into @intake.
  • Patient 103 writes in Spanish; staff read it in English and the patient reads the doctor's words in Spanish, labelled as a translation.
  • Read-aloud with macOS speech, in the matching language.

Care operations

  • Each room remembers its previous occupant (precautions, diet, notes) and the turnover checklist, done or open.
  • A diet decision opens a tray task that only room service can close.
  • DISCHARGE opens a five-task turnover checklist; READY answers from open tasks and precautions.
  • A second entry for the same medicine is flagged, never blocked or merged.
  • Opt-in reminders for room tasks left open too long.

Records and dashboards

  • Mission control: ward tiles, patient cards, cases with a pipeline, ward activity, evidence ledger, chart history, medicines, rooms, tasks, tracking, translations, reminders, command audit.
  • The shift record: every patient's words, decisions, refusals, medicines, tasks, reminders, translations and tracked items, in order.
  • Role-scoped timelines: five kinds of entry, never merged.
  • A read-only API behind all of it.

Tracking

  • Jira tasks and Google Calendar events for open cases, reported by the care-coordinator to a tracking ledger shown on the dashboard.
  • Lantern's own hooks can create the same items directly when credentials are set.
  • Neither is the medical record, and a failing integration never blocks the loop.

Trust and checks

  • The service matches people by user id, never by display name, and every side effect is idempotent.
  • A claim card must quote the patient exactly, cite an active order and the current chart version.
  • A decision needs the doctor role, the doctor room, the case thread, an unedited post and the current chart version.
  • 98 automated tests, a one-command offline demo, and fictional data throughout.
